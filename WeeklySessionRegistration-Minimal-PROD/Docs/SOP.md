# Standard Operating Procedures — Minimal Edition

Day-to-day procedures for the people who run the app (Admins and
Coordinators). End users have their own guide (`HOW-TO.md`); deployment
is covered in `../DEPLOYMENT.md`.

---

## 1. Access and roles

Roles live in the **`EventSessionRegistration_AppRoles`** SharePoint list.

| Role | Can do |
|---|---|
| **Admin** | Everything: Admin screen, events, sessions, registrations, reports |
| **Coordinator** | Same Admin screen access in this edition |
| *(not listed)* | Regular user — Intro + event page only |

### Add / change / remove someone

1. Open the `EventSessionRegistration_AppRoles` list in SharePoint.
2. **Add**: new item > pick the person in `UserEmail` > pick `Role`.
3. **Change**: edit their row's `Role`.
4. **Remove**: delete their row — they become a regular user immediately
   (on their next app start).

> **Bootstrap warning:** while the list is **empty**, the app treats
> everyone as Admin so you can't lock yourself out. Never leave the list
> empty in production — add your own Admin row first.

Also remember: app access itself is controlled by **sharing the canvas
app**; users additionally need at least **Edit (contribute)** on the four
lists (sharing the app normally prompts you to grant this).

## 2. Events

### Create an event

1. Admin screen > **Events** tab > **+ New Event**.
2. **Details tab**: name, description (rich text), dates, location,
   department, event type (Virtual / In-Person / Both), optional
   **event image** and **event link**.
3. **Settings tab**:
   - Scheduling: all-day toggle, slot duration, day start/end times.
   - People: coordinator, POC.
   - Rules: registration cutoff hours (blank = 48), max sessions per
     user (0 = unlimited), default capacity (blank = 20), meeting link.
   - **Audience**: pick a Microsoft 365 group to restrict who sees and
     registers for the event (leave off = everyone). Members must still
     have the app shared with them.
   - **Allow register for others**: enables the "For someone else"
     option in the registration modal for this event.
   - **SharePoint Site URL / List Name**: external sync (see § 5).
4. Save. The event appears in Event Management and (once it has
   sessions) to users.

### Deactivate / reactivate / delete

Use the row actions in **Event Management**. Deactivating hides the event
from users but keeps all data. Prefer deactivation over deletion —
registrations reference the event by ID.

### Promote the featured event (Intro page)

There is no Settings screen in this edition. Either:

- **Option A (recommended):** in the `EventSessionRegistration_Events`
  list, set **IsPromoted = Yes** on the new event and **No** on the old
  one. Takes effect on next app start, no republish.
- **Option B:** pin the event's item ID in `App.OnStart`
  (`Set(varPromotedEventID, <ID>)`) and republish. A pinned ID always
  wins over IsPromoted.

## 3. Sessions

### Create sessions

1. **Events** tab > event row > **+ New Session**.
2. The modal is locked to that event and only offers dates inside the
   event's start/end window; time slots follow the event's day start/end
   and slot duration (all-day events get one "All Day" slot per date).
3. Slots that already exist are marked in the picker — from there you can
   also **edit, deactivate, reactivate, or remove** an existing slot.

### Manage sessions

- **Sessions** tab: table + calendar view, filterable by event.
- Deactivate a session to stop new bookings without touching existing
  registrations. Capacity edits apply immediately.
- Removing a session does not cancel its registrations — cancel those
  first from the **Registrations** tab if needed.

## 4. Registrations and reports

### Look up / cancel a registration

1. **Registrations** tab > filter by event, status, or date range.
2. **Cancel** on a row frees the seat, marks the row `Cancelled`
   (nothing is deleted), emails the registrant, and — if the event has
   external sync — updates the external list.

### Reports

- **Download CSV**: Reports tab > set filters > **Download CSV**
  (generated by the `EventSession_ExportCSV` flow; the file also lands in
  the flow owner's OneDrive `/CSV Exports` folder).
- **Send Report**: opens a modal — pick recipients (people picker), add
  a note, send. Delivers the CSV as an email attachment via
  `EventSession_SendReportEmail`.
- Practical export ceiling is a few thousand rows per run; for large
  events, export per date range.

## 5. External list sync (per event)

Mirrors an event's registrations into any other SharePoint list
(register = create row, switch = update, cancel = mark `Cancelled`).

### Enable for an event

1. Provision the target list (one-time, per list):

```powershell
.\SetupExternalList-Graph.ps1 -SiteUrl "https://tenant.sharepoint.com/sites/OtherSite" -ListName "YourList" [-WithScenarioColumns]
```

2. Admin > edit the event > **Settings** > set **SharePoint Site URL**
   and **SharePoint List Name**.
3. Confirm the flows' SharePoint connection owner has **Edit** on the
   target site.

### Disable

Blank out the event's SPSiteURL or SPListName. Existing external rows are
left as-is.

### Verify / troubleshoot

- Check the run history of **`EventSession_SyncExternalList`**.
- Column requirements are in `LISTS.md` § 6. Optional `staff` / `author`
  / `hour` columns are auto-detected — the flow skips them when absent.
- The app shows a warning notification if a sync call fails; the
  registration itself still succeeds (sync is best-effort).

## 6. Notifications

| Notification | Sent by | Wording lives in |
|---|---|---|
| Register / switch / cancel email + Teams card | `EventSession_SendAppEmail` | The **screens** (Power Fx): `btnRegModalConfirm_EvQ`, `btnCancelEvQConfirm` in `scrEventQuickReg.yaml`; `btnRRowCancel` in `scrAdmin.yaml` |
| Day-before reminder (7 AM ET) + Teams card | `EventSession_SessionReminderDaily` | Inside the flow definition |
| Share-event email | `EventSession_ShareEvent` | Inside the flow definition |
| Report email | `EventSession_SendReportEmail` | Inside the flow definition |

All emails are wrapped in the branded HTML shell by the flows. Changing
screen-based wording requires editing the YAML/formula and republishing
the app. Emails send from the **Outlook connection owner**; to send as a
shared mailbox, edit the flow's send action ("Send an email from a shared
mailbox").

## 7. Routine maintenance

| Cadence | Task |
|---|---|
| Weekly | Skim flow run histories for failures (especially SendAppEmail and SyncExternalList) |
| Before each event | Confirm sessions exist, capacity is right, promoted event is current |
| Monthly | Review AppRoles membership; archive/export old registrations if lists grow past a few thousand rows |
| When slots run out | Seed more via Admin > New Session, or re-run `CreateLists-Graph.ps1 -WeeksToSeed N` for the General Sessions event |
| After tenant changes | If the flow connection owner leaves, reassign flow ownership and reconnect the four connections |

## 8. Incident quick reference

| Report | Likely cause / action |
|---|---|
| "I didn't get the email" | Flow off or connection broken — run history of SendAppEmail; check junk folder |
| "I can't register" (button disabled) | Required fields not filled, session full, cutoff passed, or MaxPerUser reached — the modal note says which |
| "I can't see the event" | Event inactive, audience group restriction, or app not shared with them |
| "Everyone can see the Admin button" | AppRoles list is empty (bootstrap mode) — add the Admin row |
| External list stale | See § 5 verify steps |
| CSV won't open in Excel | Re-download; if persistent, check ExportCSV flow output encoding in run history |
